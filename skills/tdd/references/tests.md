# Behavioral Tests

A durable test describes caller-visible capability through a public interface and survives an implementation rewrite.

```typescript
test("a confirmed order can be retrieved", async () => {
  const order = await confirmOrder(knownCart, acceptedPayment)

  expect(await getOrder(order.id)).toEqual({ id: order.id, status: "confirmed" })
})
```

## Keep

- names that state observable behavior;
- setup through public interfaces;
- verification through the same or another public interface;
- known literals, worked examples, or specification values as expectations;
- one coherent behavior per test.

## Reject

- private-method tests and assertions about internal collaborator calls;
- database queries or logs used as side channels when a public retrieval interface exists;
- expected values recomputed with the implementation's algorithm;
- snapshots whose expected shape was generated by the code under test;
- tests that fail solely because internal structure changed;
- horizontal batches written before any production slice is exercised.
